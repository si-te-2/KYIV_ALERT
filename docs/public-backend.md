# Публічний C# API для GitHub Pages

Frontend: https://si-te-2.github.io/KYIV_ALERT/. Backend: ASP.NET Core 10 у Docker.
Файли `Dockerfile` та `render.yaml` готують один вебсервіс Render Free без платної бази чи диска.
Це підготовлена конфігурація, а не підтвердження фактичного розгортання.

## Розгортання без секретів

1. Увійдіть у Render. Якщо GitHub запитує нові дозволи або Render пропонує прийняти умови, власник облікового запису має перевірити й погодити їх.
2. Створіть Blueprint з репозиторію `si-te-2/KYIV_ALERT`, гілка `main`, файл `render.yaml`. Перевірте план **Free**, один екземпляр і відсутність платних ресурсів. Не додавайте платіжний метод для цього завдання.
3. Дочекайтеся успішного `/api/health`. `CivilAlerts__Enabled=false` навмисно залишає Telegram вимкненим до налаштування приватного доступу.
4. Задайте GitHub Actions **repository variable** `PUBLIC_API_ORIGIN` рівною фактичній HTTPS-адресі сервісу Render, без шляху. Це публічна адреса, не секрет. Повторно запустіть workflow Publish GitHub Pages.

Браузер отримує лише `/api/drone-warnings`. Він не авторизується в Telegram. CORS дозволяє GET з `https://si-te-2.github.io`, без cookies/credentials. CORS не є автентифікацією: ці агреговані регіональні попередження навмисно публічні. `/api/status` із синтетичними демонстраційними повідомленнями на хмарному API вимкнено через `PublicApi__ReadOnly=true`. Загальна карта тривог надалі використовує відкритий потік незалежно від доступності Telegram-сервера.

## Підключення Telegram — лише після окремого погодження

Сесія `account.session` дає доступ до особистого Telegram-акаунта. Її перенесення означає передавання облікових даних провайдеру Render. Не завантажуйте сесію, API hash або коди входу в GitHub, workflow artifacts, журнал чи чат. Відвідувачам сайта вони не потрібні.

Перед перенесенням зупиніть локальний читач і консоль входу: не запускайте одночасно хмарний і локальний клієнт із копіями тієї самої сесії. Підготуйте актуальну сесію через наявну локальну команду входу. Власник може відкликати її в Telegram → Пристрої; це також зупинить хмарне підключення.

Після згоди власника:

1. У середовищі сервісу Render задайте `Telegram__ApiId` та `Telegram__ApiHash` приватними змінними з наявної локальної конфігурації. Не задавайте їх через Vite.
2. У Render **Secret Files** додайте `telegram-session.base64`: Base64-вміст актуального бінарного session-файла, отриманий локально без виведення в журнал. Base64 не шифрує дані — це все ще секрет.
3. Задайте `Telegram__SessionSeedFile=/etc/secrets/telegram-session.base64` і `CivilAlerts__Enabled=true`. `Telegram__SessionDirectory=/tmp/kyiv-alert-telegram` вже задано в Blueprint. Сервер копіює сесію в приватний каталог для запису, не змінюючи secret file. На Linux каталог має права 0700, файл — 0600. Наявна робоча сесія не перезаписується.
4. Збережіть і перезапустіть сервіс. Непридатна або відкликана сесія повертає недоступність потоку; сервер не запитує номер, пароль чи код входу через публічний API.

## Обмеження Free та перевірка

За [документацією Render Free](https://render.com/docs/free), сервіс засинає після 15 хвилин без вхідних запитів. Пробудження займає приблизно хвилину. Файлова система очищується при перезапуску, розгортанні й засинанні; сесія відновлюється з Secret File. Якщо Telegram відхиляє стару копію, потрібне окреме оновлення секрету. Немає гарантії безперервного моніторингу, а безкоштовні ліміти можуть призупинити сервіс. Не використовуйте штучні keep-alive запити для обходу лімітів.

Перевірте `/api/drone-warnings`: `ready` означає актуальне успішне читання, а порожній масив не доводить відсутності загрози. Звірте час і першоджерела. Відсутність нових повідомлень не є підставою вигадувати маркери. Перевірте недоступність API: сайт має показувати збій, а загальна карта тривог має продовжити працювати. Після зміни адреси API перебудуйте GitHub Pages.

CI збирає Docker image та перевіряє health, CORS і відсутність демонстраційного endpoint. Тести Telegram використовують фікстури; реальне читання перевіряється лише після приватного налаштування сервісу.

Для відкату приберіть `PUBLIC_API_ORIGIN` і повторно запустіть Pages. Зупиніть сервіс Render, вилучіть його секрети й відкличте сесію в Telegram, якщо хмарний доступ більше не потрібен.
